# MultiStore — منصة المتاجر الإلكترونية متعددة البائعين

نسخة موحدة مبنية على Next.js 15 App Router + TypeScript + Tailwind CSS 4 + Prisma 6 + PostgreSQL + Auth.js v5، مع اعتماد لوحة ألوان وتصميم عربي أنيق مستوحى من ملف الواجهات المرفق. لا يحتوي الملف على أسرار أو ملف `.env` حقيقي.

## ما تتضمنه هذه الحزمة

- صفحة تسويقية عربية responsive، أقسام المزايا وخطوات العمل والأسعار والأسئلة الشائعة.
- تسجيل حساب مالك متجر وإنشاء متجر أولي، تسجيل دخول Credentials، حماية مسارات لوحة المتجر والإدارة العليا حسب الدور.
- مخطط Prisma متعدد الجداول: المستخدمون، المتاجر، العضويات، المنتجات والمتغيرات، التصنيفات الشجرية، العملاء والعناوين، الطلبات وعناصرها، الكوبونات، العروض، الولاء، التقييمات، قوائم الرغبات، سجلات الرسائل والحملات، سجل النشاط، إعدادات المنصة، الخطط والاشتراكات والفواتير وصفحات المتجر.
- عزل استعلامات لوحة المتجر عبر shopId في الصفحات وواجهات API المكتملة في هذه النسخة (خصوصًا المنتجات والإعدادات وإنشاء الطلب).
- إدارة منتجات CRUD أساسية مع معاينة صور وروابط Cloudinary، بحث، حالات المنتج، ومربع تأكيد وتنبيهات موحدة.
- صفحة إعدادات تشمل الهوية، الاتصال، العملة واللغة والاتجاه والمنطقة الزمنية والضرائب وSEO.
- لوحة إدارة عليا للمتاجر والمستخدمين والاشتراكات والنشاط والإعدادات (عرض بيانات حاليًا).
- واجهة متجر عامة لكل `/shop/[slug]`، صفحات منتجات، وسلة محلية عبر localStorage، PWA/manifest/service worker، وhealth endpoint.
- نسخ من الأصول الرسومية وCSS/JS من حزمة التصميم الأخيرة تحت `public/images/marketing` و`public/css` و`public/js`.

## تشغيل محلي

1. ثبّت Bun وPostgreSQL (محلي أو Neon).
2. فك الضغط وادخل إلى مجلد المشروع.
3. انسخ `.env.example` إلى `.env` وأدخل `DATABASE_URL` و`AUTH_SECRET` و`AUTH_URL`.
4. شغّل:

```bash
bun install
bunx prisma generate
bunx prisma migrate dev --name init
bun run db:seed
bun run dev
```

افتح `http://localhost:3000`. لا يُنشأ حساب Super Admin تلقائيًا؛ عيّن `SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD` في البيئة قبل تشغيل seed، ثم سجّل الدخول. بيانات Admin يجب أن تكون قوية ولا تُستخدم في الإنتاج قبل تأمين إدارة الأسرار.

## نشر Vercel + Neon

- أنشئ قاعدة Neon PostgreSQL، واضبط `DATABASE_URL` باستخدام SSL.
- اضبط `AUTH_SECRET` بقيمة عشوائية طويلة و`AUTH_URL`/`NEXT_PUBLIC_APP_URL` للنطاق الفعلي.
- شغّل migrations في خطوة نشر محكومة: `bunx prisma migrate deploy`، ثم ابنِ التطبيق.
- راجع سياسات النسخ الاحتياطي، وسجلات الأخطاء، وقيود المعدل، وDNS/HTTPS قبل فتح التسجيل العام.

## حدود يجب الانتباه لها قبل الإنتاج

هذه حزمة تنفيذ واسعة/نسخة أولية متكاملة الهيكل وليست شهادة أن كل وظيفة إنتاجية قد اختُبرت. يجب تشغيل typecheck/build والمهاجرات واختبارات end-to-end على بيئة تحتوي قاعدة PostgreSQL حقيقية. بوابات الدفع والبريد وSMS وWhatsApp وPush الفعلية، محرر القص/التدوير النهائي، رفع Cloudinary الآمن من الخادم، استعادة كلمات المرور، 2FA الفعلي، إدارة أدوار الموظفين التفصيلية، التصدير PDF/Excel، النسخ الاحتياطي المجدول، Redis/ISR، وحالات الشحن المتقدمة تحتاج ربط مزوديها واختبارها قبل الإعلان عنها كجاهزة. لا توجد بيانات اعتماد تجريبية داخل الحزمة. لا تضع مفاتيح أو أسرارًا في Git أو ZIP.

## الأمان والعزل

- واجهات المنتجات والإعدادات تستخدم جلسة Auth.js وتتحقق من عضوية المتجر الحالي وتقيّد العمليات بـ `shopId`.
- إنشاء الطلب يتحقق من أن المنتجات تابعة للمتجر المطلوب ويخفض المخزون ضمن معاملة؛ قبل الإنتاج أضف حجز مخزون/قفلًا متزامنًا، حدّ معدل للطلبات، حماية ضد الروبوتات، تحقق عنوان الشحن، وإشعارات بعد المعاملة.
- لا تُفعّل الدفع الإلكتروني أو Webhooks قبل التوقيع والتحقق من callbacks. لا تعتمد على معرف المتجر القادم من العميل وحده في أي عملية حساسة.
- النسخ الاحتياطي والمراقبة ومزودات الإرسال ليست مفعّلة تلقائيًا.
